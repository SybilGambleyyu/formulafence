# CI integration

Keep an approved workbook and policy in version control (or obtain the approved
artifact from your release process), then compare the candidate generated by the
same build job.

```yaml
name: Spreadsheet controls

on:
  pull_request:

jobs:
  formulafence:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - run: python -m pip install formulafence
      - run: >-
          formulafence check
          models/approved/model.xlsx
          build/model.xlsx
          --policy models/formulafence.yml
          --format markdown
          --output formulafence-report.md
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: formulafence-report
          path: formulafence-report.md
```

For systems that ingest SARIF, switch `--format markdown` to `--format sarif`
and write to `formulafence.sarif`. FormulaFence uses logical locations such as
`Dashboard!B12`; consumers that do not understand Excel coordinates can still
show the workbook path, rule, and message.

The repository's own [CI workflow](../.github/workflows/ci.yml) lint-checks,
tests, and builds the package. It intentionally does not require Excel or a
networked spreadsheet service.
